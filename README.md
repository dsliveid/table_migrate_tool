## 🌟 核心特性

### 1. 工具箱聚合导航
* **开箱即用聚合中心**：启动程序即呈现现代化工具箱主界面，功能分区清晰，支持在“表结构迁移”与“表结构导出”之间无缝切换。各向导界面顶部配备“‹ 返回工具箱”按键。
* **全局数据源与方案统一管理**：工具箱顶部集中提供数据源配置入口、迁移方案管理与导出方案管理，配置随身携带。

### 2. 功能一：表结构与数据迁移
* **跨库/跨实例精准迁移**：支持单表或批量对象筛选，目标库不存在时自动创建。
* **智能增量比对 (Smart Alter / Diff)**：自动比对新增列、修改字段长度/类型（`ALTER TABLE ADD / ALTER COLUMN`）。
* **先删后建强力兜底 (Drop and Recreate)**：针对主键重构等常规 ALTER 无法解决的痛点，自动解开依赖外键，先 `DROP TABLE` 再全新 `CREATE TABLE`。若包含数据则全量拉取还原。
* **视图依赖多轮重试与自定义调整**：视图强制锁定仅迁移结构定义，支持多轮依赖拓扑重试，支持单视图在线调整与批量查找替换跨库 SQL。

### 3. 功能二：表结构与数据导出
* **灵活的对象与数据导出**：支持单独导出表结构、单独导出视图定义，或导出表结构+数据（支持单表独立控制）。
* **智能打包与格式输出**：
  * **仅导出结构**：默认输出为**单个 SQL 脚本文件（.sql）**。
  * **包含表数据且多表**：默认每个表独立生成一个 `.sql` 脚本，视图汇总为独立脚本，导出结果**自动合并打包为一个 ZIP 压缩包（.zip）**。
  * 界面同时提供单选模式供用户自由切换单文件或压缩包，支持自定义输出路径。
* **高质量 SQL 生成**：生成标准 T-SQL，包含 `DROP TABLE IF EXISTS` 预检查、主键、辅助索引与扩展属性中文注释（MS_Description）；数据导出自动分批写入并维护 `SET IDENTITY_INSERT ON / OFF`；采用 UTF-8 BOM 编码，避免 SSMS 中文乱码。
* **导出方案保存与复用**：支持将数据源、选定对象、导出规则及自定义 SQL 保存为导出方案，随时一键载入复用。

## 🛠 核心机制说明

### 1. 视图只读约束与依赖处理
* **强制无数据规则**：视图是虚拟表与查询映射，迁移数据无意义且会导致 SQL Server 异常。本工具在 UI 交互与执行引擎中**强制锁定视图只迁移结构定义**，无法更改。
* **多轮依赖拓扑重试**：视图之间往往存在嵌套依赖（视图 A 引用视图 B）。迁移引擎在执行视图 DDL 时采用多轮重试算法（默认 3 轮），待被依赖的底层视图建好后，上层依赖视图自动在下一轮重试中创建成功。

### 2. 多次迁移与冲突解决策略

| 策略模式 | 适用场景 | 执行逻辑 | 数据安全性 |
| :--- | :--- | :--- | :--- |
| **智能增量比对 (Diff) [默认推荐]** | 日常结构演化、新加字段、修改字段长度/精度 | 比对源与目标的差异，执行 `ALTER TABLE ADD/ALTER COLUMN`；遇主键变动时自动提供兜底选项。 | **最高**，目标表已有数据完全保留。 |
| **先删后建兜底 (Recreate) [强力兜底]** | 主键变更（单列变复合）、字段不兼容强转、约束冲突严重 | 解除引用该表的外键关联约束 ➔ `DROP TABLE` ➔ 全新 `CREATE TABLE` ➔ 重新建立约束与索引。 | 若勾选【含数据】，重建后从源端全量拉取还原；若【仅结构】，目标表历史数据将清空（有强制弹窗警告）。 |
| **跳过已有 (Skip)** | 仅补充目标端缺失的新表 | 目标库已存在的表保持原样，只创建目标库没有的新表。 | **绝对安全**，不修改目标表。 |

### 3. 绿色便携与数据隔离模式
所有的运行时持久化均位于程序同级目录的 `./data/`：
* `data/app.db`：嵌入式 SQLite 数据库，用于存储保存的数据源配置与迁移方案。
* `data/.secret.key`：应用程序启动时自动生成的对称加密密钥，用于密码加解密。
* `data/logs/`：存储历史迁移日志与导出的文本报告。

无论将包含程序与 `data` 的文件夹移动至哪台电脑或哪个盘符，配置均自闭环流动。

## 📖 向导式操作指引

```mermaid
flowchart LR
    S1[步骤1: 数据源与库] --> S2[步骤2: 筛选对象与规则]
    S2 --> S3[步骤3: 冲突策略配置]
    S3 --> S4[步骤4: 确认与保存方案]
    S4 --> S5[步骤5: 自动化迁移执行]
```

### 步骤 1：数据源与数据库配置
1. 点击右上角【⚙ 数据源配置】，添加并测试来源与目标 SQL Server 连接。
2. 在下拉框中选择来源数据源及来源数据库。
3. 选择目标数据源及目标数据库（支持下拉选择已有库，或直接输入新建库名）。
4. 点击【下一步：选择迁移对象】。

### 步骤 2：筛选迁移对象与内容模式
1. 界面自动展示来源数据库的所有用户表与视图。
2. 默认状态为**全选**。
3. 可使用顶部搜索框快速搜索过滤，或使用【仅选所有表】/【仅选所有视图】。
4. 针对普通表，可在右侧切换【仅迁移表结构】或【表结构 ＋ 数据】（支持顶部批量设置）。
5. 视图行的迁移内容列强制锁定为【仅迁移结构 (视图默认只读)】。
6. 点击【下一步：配置冲突策略】。

### 步骤 3：选择冲突与更新策略
1. 根据目标库是否已有旧表选择策略：
   * **策略 A（智能增量比对）**：推荐选项，默认自动开启“遇主键变动自动允许先删后建兜底”。
   * **策略 B（先删后建兜底）**：彻底解决主键或强约束冲突。
   * **策略 C（已存在则跳过）**：仅同步缺失的新对象。
2. 点击【下一步：方案确认与保存】。

### 步骤 4：确认清单与保存方案
1. 浏览本次迁移汇总卡片与待迁移清单文本。
2. **保存方案（可选）**：点击【💾 保存当前配置为迁移方案】，输入名称后即可存入本地库。下次在主界面点击【📋 方案管理】即可一键载入复用。
3. 点击【🚀 确认并开始自动迁移】。若存在高危先删后建且不迁数据情况，系统将弹出二次风险提示。

### 步骤 5：自动化迁移与监控
1. 观察实时进度条与正在处理的对象名称。
2. 查看控制台输出的彩色实时日志（包含表结构建立、增量更新、自增列 `IDENTITY_INSERT` 处理、数据行数导入耗时、视图创建与重试等）。
3. 支持点击【⏹ 中止迁移】随时安全停止，或点击【导出日志文件】保存本次迁移记录。

## 🚀 快速开始

### 方式 A：直接运行绿色单文件版（推荐）
在本项目打包完成后，直接进入输出目录 `dist/`，双击运行 **`TableMigrateTool.exe`** 即可直接使用：
* **单个独立程序**：无需解压文件夹，无需任何 Python 运行环境或额外驱动。
* **数据目录自愈自建**：首次运行自动在同级目录下创建 `data/` 目录存放配置和日志，随拷随用。

### 方式 B：从源码启动开发

#### 1. 准备并激活 venv 虚拟环境
推荐使用 Python 3.10 及以上环境。
```bash
# 进入工程目录
cd table_migrate_tool

# 创建虚拟环境
python -m venv .venv

# 激活虚拟环境 (Windows PowerShell)
.\.venv\Scripts\Activate.ps1
# 或 Windows CMD
.\.venv\Scripts\activate.bat
# 或 Linux / macOS
source .venv/bin/activate

# 安装项目依赖 (已包含核心依赖及 PyInstaller 打包工具)
pip install -r requirements.txt
```

#### 2. 启动应用
```bash
# 方式 1: 使用快捷脚本
./run.sh

# 方式 2: 使用 Python 命令
python main.py
```

## ❓ 常见问题与排查 (FAQ)

#### Q1: 测试连接时提示 `Adaptive Server is unavailable or does not exist`？
* 请检查目标 SQL Server 服务器 IP 和端口（默认 1433）是否填写正确。
* 确保 SQL Server 配置管理器中已启用 **TCP/IP** 协议。
* 检查目标服务器 Windows 防火墙是否放行了 1433 端口入站规则。

#### Q2: 目标端包含自增列（IDENTITY）时数据能正常导入吗？
* 可以。迁移引擎内置了自增列识别机制，在批量写入数据前会自动执行 `SET IDENTITY_INSERT [table] ON`，写入完成后自动执行 `OFF`，确保自增 ID 与源库保持绝对一致。

#### Q3: 视图创建遇到 `Invalid object name` 报错？
* 视图间存在相互嵌套依赖。工具内部设计了多轮重试机制，会在表和基础视图创建成功后再次重试依赖视图，通常可在第 2 轮或第 3 轮自动修复。

#### Q4: 数据文件迁移到其他机器后，之前的方案还在吗？
* 依然存在。所有方案与连接信息均保存在程序同级目录的 `data/app.db` 文件中。只要整包复制移动，所有配置与方案均完好保留。
